# Подключение CR_Newsletters

1. Разверните этот репозиторий как отдельный Cloudflare Worker через `npm run deploy` или интеграцию Workers & Pages. Конфигурация `wrangler.jsonc` создаёт отдельное SQL Durable Object `NewsletterStore`; используйте отдельное имя `cr-newsletters` и не меняйте привязку CR_Reserve.
2. В настройках Worker задайте **Secrets** `BOT_TOKEN` от @CR_Newsletters_Bot, `ADMIN_IDS` (числовой Telegram ID владельца; несколько ID через запятую) и `ORDER_CHAT_ID` (ID рабочего канала `-100…` либо `@username` публичного канала). Токен храните только в Cloudflare, не в GitHub и не в коде. `WEBHOOK_SECRET` необязателен: кнопка «Подключить бота» безопасно создаёт собственный секрет в хранилище.
3. Добавьте @CR_Newsletters_Bot администратором канала с разрешением публикации. Для приватного канала после установки `BOT_TOKEN` и `ADMIN_IDS` откройте бота и перешлите ему сообщение из канала с сохранением источника. Он сообщит ID канала; внесите его в `ORDER_CHAT_ID` и повторно разверните Worker.
4. В @BotFather создайте Mini App для @CR_Newsletters_Bot, укажите **фактический HTTPS-адрес** нового Worker. Если BotFather выдаст короткую ссылку вида `https://t.me/CR_Newsletters_Bot/<app>`, используйте её для входа. Меню бота также настраивается внутри приложения.
5. Откройте Mini App своим Telegram-аккаунтом → **Управление → Подключить бота**. Это настроит webhook, команды и кнопку «Поступление». Если нужно, `npm run dev` предоставляет локальную проверку, но вход Telegram и доставка в канал требуют публичный HTTPS.
6. Добавьте менеджеров в «Управление → Менеджеры», затем «+ Поступление» → загрузите Excel → проверьте товары, цены и замечания → статус «В продаже» → сохраните. Поддерживается отчёт остатков: Код, Наименование, Изображение, Доступно, Цена продажи. Excel загружается в браузере владельца; перед сохранением можно заполнить цены, а фото сжимаются.

Пока `BOT_TOKEN` не задан, приложение показывает только демонстрационный предпросмотр. При отсутствующем `ORDER_CHAT_ID` оформление заказов заблокировано, чтобы заказ не потерялся без канала. Изменение количества в опубликованном поступлении не может сделать остаток ниже уже оформленных заказов. При повторном импорте файл содержит **исходное количество**, а не текущий остаток.


## Колонки отчёта остатков

| В Excel | В приложении |
|---|---|
| Код | Артикул |
| Наименование | Наименование |
| Изображение | Изображение |
| Доступно | Кол-во |
| Цена продажи | Цена |

«Код» имеет приоритет над «Артикул», «Доступно» — над «Остаток» и «Кол-во», «Цена продажи» — над другими ценами. «Резерв» и «Сумма продажи» не используются для расчёта количества и цены. Пустая цена продажи требует заполнения перед сохранением, даже если другая цена указана. Порядок колонок и регистр названий не важны. Встроенные фото XLS/XLSX сопоставляются с товарами по строкам и сжимаются при импорте.

## Предложения групп при импорте

После чтения Excel приложение анализирует наименования локально: объединяет синонимы типов, ищет общие начала названий незнакомых товаров, признаки подтипов, серии, коды моделей и повторяющиеся части названий. Внешний ИИ и отдельный API-ключ не требуются. Это предложения по тексту, а не гарантированное определение товара: если признаков недостаточно, подгруппа остаётся пустой и товар отмечается для проверки.

В блоке «Группы по названиям товаров» можно переименовать группу целиком, перенести отдельную позицию в существующую или новую группу и изменить подгруппу. Перед сохранением нового импорта нужно отметить «Группы и подгруппы проверены». Разметка сохраняется с товарами и видна покупателям. При обновлении того же поступления сохранённые группы сохраняются для совпадающих артикулов; новые позиции анализируются заново. Для старого поступления разметку можно проверить и сохранить через «Изменить», без повторной загрузки Excel.
